# 行车记录仪转存

将OTG读卡器中选定目录的视频复制到Android手机，完整校验后可手动清理TF卡，再手动上传到私有OSS。服务端使用云函数与MongoDB，同一空间的手机共享已上传列表。

Android0.6.4：卡上删除逐个处理并显示文件计数，不重复读取视频或显示字节速度；启动先检查更新，随后检测TF卡；检测结果直接显示在页面，不弹检测对话框。点拷贝后先快速列出文件并启动前台任务，逐文件显示SHA-256检查与暂停进度；相同内容跳过重复拷贝，旧的相同私有副本在再次扫描时核对整理；新手机与云端视频均使用统一目录。完整需求和验收方法见 [实施计划](docs/PLAN.md)。

| 目录 | 用途 |
|---|---|
| `android/` | Android客户端，第一版交付目标 |
| `server/` | 云函数控制接口，不转发视频字节 |
| `ios/` | 后续客户端预留 |
| `deploy/` | 临时目录构建、云函数部署、私有OSS发布与真实链路验证 |
| `.github/workflows/` | 自动验证与GitHub OIDC发行 |

所有敏感配置从Infisical读取，不进入Git。自建部署使用自己的私有Bucket、数据库与访问身份；源码不包含个人生产凭据。

开发与生产分别使用独立的private Bucket、RAM用户、云函数和MongoDB数据库。开发Android应用ID带 `.dev`，可与生产版同时安装。

开发者构建（SDK35、Java21、uv）：

```sh
cd server
uv sync --locked
uv run pytest -q
# 本机已安装mongod时可验证独立真实数据库
uv run python tests/run_local_mongo.py
cd ..
python deploy/build_android.py debug
```

发行任务使用版本标签 `vMAJOR.MINOR.PATCH`。Infisical domain/project/identity通过仓库Variables配置；真实敏感值由OIDC读取，不使用GitHub Secrets，不上传个人配置APK到公开GitHub附件。

## 操作流程

0.4.0简化为两页，无底部选项卡：

1. **卡→手机**：插入TF卡，选择视频目录（展示完整绝对路径），点拷贝。完整校验后仍保留源视频，用户可手动点删除；再点下一步。
2. **手机→云端**：点上传，完成云端核验后仍保留手机视频；用户可单独点清理手机副本。

没有自动删除、自动上传或拷贝后衔接任务。移动网络上传需确认流量；历史批次和更新在更多菜单。每个按钮只做一件事。

上传完整核验后，手动清理新版本的应用私有手机副本会直接删除文件；旧版共享媒体副本继续使用系统回收站兼容流程。TF卡原视频只有用户手动确认后才删除，删除前检查副本存在及大小、卡上大小及修改时间，不再次整文件读取；删除按文件计数显示。放弃未完成任务会清除手机副本、本地任务和进度，不删除TF卡原文件或已上传的云端视频。

手机重复判断会实际读取源文件与已有副本的SHA-256和长度，内容相同才跳过；同一批扫描的改名重复文件也只保留一份。新手机副本使用`videos/SHA256.扩展名`，新云端对象使用`videos/SHA256_原文件名`；历史批次只作为记录，不决定新文件目录。既有云端对象不迁移、不删除，续传沿用已登记路径。
